# juya-admin 云效与 ECS 静态部署设计

## 1. 背景与目标

`juya-admin` 当前托管在 GitHub 仓库 `zhanjiangmrlu/juya-admin`，没有生产部署文件。项目使用 Vue 3、Vite 和 Vue Router History 模式，生产构建输出 `dist`。本次只部署管理后台静态前端，不部署 `juya-admin-api`，也不要求登录或其他业务接口可用。

本次交付目标是建立区分测试与生产环境的云效 Flow 发布路径。测试环境只从 GitHub `test` 分支构建，生产环境只从 GitHub `main` 分支构建。本次仅将测试构建产物发布到公网 IP 为 `8.163.84.24` 的测试 ECS，并通过 `http://8.163.84.24` 访问前端页面；不创建或执行生产部署。

## 2. 已确认方案

- GitHub 仓库继续作为唯一代码源，不迁移或镜像到云效 Codeup
- 使用云效 Flow 的 GitHub 服务连接拉取代码并执行质量门禁与生产构建
- GitHub `test` 分支只触发测试构建与测试环境部署
- GitHub `main` 分支只触发生产构建与生产环境部署
- 本次只创建并运行测试环境发布链路；生产环境目标保持未配置状态
- 使用锁定版本的 Node.js 22.22.x 和 pnpm 11.22.0
- 将 `dist` 打包为不可变发布制品，由云效 ECS 主机部署任务传送到目标主机
- ECS 使用 Nginx 监听 80 端口并托管静态文件
- 每个环境使用独立发布根目录；每次发布进入独立版本目录，通过符号链接原子切换当前版本
- 保留上一个成功版本，部署或健康检查失败时自动回滚
- 本次不配置 `/api` 反向代理；后端部署后再增加同源代理
- 本次不配置域名、HTTPS、OSS 或 CDN

## 3. 方案选择

### 3.1 采用：云效制品发布到 ECS + Nginx

该方案直接满足使用 ECS 公网 IP 访问的目标，依赖少，构建与运行分离，并能复用云效主机组、审批、审计和回滚能力。

### 3.2 未采用：Nginx 容器镜像 + ACR

容器方案能提供完全一致的运行环境，但会额外引入 Docker、ACR 仓库、镜像凭据和镜像生命周期。对于当前只发布静态文件的目标复杂度过高。

### 3.3 未采用：OSS 静态托管 + CDN

OSS/CDN 更适合正式生产的静态资源分发，但访问入口将是 OSS/CDN 地址或绑定域名，不能直接以当前 ECS 公网 IP 作为页面地址。

## 4. 环境与分支映射

| 环境 | GitHub 分支 | 部署目标                     | 发布根目录                   | 本次执行 |
| ---- | ----------- | ---------------------------- | ---------------------------- | -------- |
| 测试 | `test`      | ECS `8.163.84.24`            | `/opt/juya-admin/test`       | 是       |
| 生产 | `main`      | 独立生产目标，由生产变量指定 | `/opt/juya-admin/production` | 否       |

流水线必须在构建和部署两个阶段都校验当前 Git 分支与目标环境的映射。`test` 分支不能读取或选择生产主机组，`main` 分支不能部署到测试主机组。手动运行也不能绕过该校验。

测试与生产分别使用独立的云效环境、主机组、变量组、审批策略、制品命名空间和发布目录。任何生产主机、域名或凭据在本次任务中均不配置、不推断、不访问。

## 5. 组件与文件边界

### 5.1 云效流水线

GitHub 仓库新增 `.aliyun-ci.yml`，由云效 Flow 读取该文件。测试流水线的代码源和触发器固定为 `test` 分支。流水线包含以下阶段：

1. 安装固定 pnpm 版本并使用锁文件安装依赖
2. 运行 `pnpm check`
3. 运行 `pnpm test`
4. 运行 `pnpm build`
5. 将 `dist` 与部署文件打包为发布制品
6. 校验当前分支为 `test`，通过测试 ECS 主机组执行部署脚本
7. 从 ECS 本机和公网入口执行静态页面健康检查

云效中的组织 ID、GitHub 服务连接、测试主机组 ID 等平台资源只作为测试变量组引用，不写死进仓库。生产变量组与测试变量组完全分离，且本次不配置生产变量。GitHub 授权仅授予读取该仓库以及读取提交状态所需的最小权限；密码、令牌和 SSH 凭据不得进入仓库或构建日志。

### 5.2 ECS 发布脚本

仓库新增 `deploy/ecs-deploy.sh`。脚本负责：

- 校验制品包含 `index.html` 和 `assets` 目录
- 要求显式传入 `test` 或 `production` 环境参数，并验证云效分支信息
- 测试制品解压到 `/opt/juya-admin/test/releases/<release-id>`
- 生产制品仅允许从 `main` 分支解压到 `/opt/juya-admin/production/releases/<release-id>`，本次不执行
- 设置静态文件为只读，确保 Nginx 可读取
- 原子更新对应环境根目录下的 `current` 符号链接
- 校验并重载 Nginx 配置
- 访问 `http://127.0.0.1/` 验证首页
- 失败时恢复原符号链接并再次重载 Nginx
- 成功后仅保留最近两个发布目录

部署脚本不自动安装系统软件，不修改防火墙或安全组。ECS 必须预先安装并启动 Nginx，云效部署账号必须具备写入发布目录、安装 Nginx 站点配置及重载 Nginx 的最小权限。

### 5.3 Nginx 配置

仓库新增 `deploy/nginx/juya-admin.conf`，核心行为如下：

- 监听 `0.0.0.0:80`
- 测试站点以 `/opt/juya-admin/test/current` 作为根目录
- `/` 使用 `try_files $uri $uri/ /index.html` 支持 Vue History 路由
- `index.html` 禁止长期缓存，确保发布后及时取得新入口文件
- 带内容哈希的 `/assets/` 使用长期缓存
- 禁止访问隐藏文件并添加基础安全响应头
- 暂不代理 `/api`；请求会返回明确的 503，避免误路由到前端 `index.html`

## 6. 发布与回滚流程

```text
GitHub test 分支提交
  → 云效质量门禁
  → Vite production build
  → dist 发布制品
  → 测试 ECS 版本目录
  → Nginx 配置校验
  → current 原子切换
  → Nginx 重载
  → 本机与公网健康检查
  → 成功保留 / 失败自动回滚
```

发布 ID 优先使用云效构建号与 Git 提交 SHA 的组合，确保可以追溯制品来源。任何构建、传输、Nginx 配置校验、重载或健康检查失败都必须让流水线失败，不允许带病发布。

生产环境未来采用同样的构建与回滚结构，但只能由 `main` 分支触发并使用独立生产资源。测试成功不会自动触发生产发布。

## 7. 环境前置条件

- ECS 安全组入方向放通 TCP 80；22 端口只允许受控来源访问
- ECS 已安装并运行 Nginx
- 云效中已经创建或将创建只包含 `8.163.84.24` 的测试 ECS 主机组
- 云效主机部署账号具备所需的最小 `sudo` 权限
- GitHub 仓库 `zhanjiangmrlu/juya-admin` 已通过云效代码源服务连接授权
- GitHub 当前尚无 `test` 分支；实施时从已确认的当前代码基线创建 `test` 分支后再配置测试触发器
- 云效测试 Flow 的代码源和触发器均指向 GitHub `test` 分支，不使用云效 Codeup 仓库
- 生产 Flow 只允许指向 GitHub `main` 分支，但本次不创建生产部署目标或运行生产 Flow
- 域名和 HTTPS 不在本次范围内

如果实际 ECS 操作系统、Nginx安装方式或云效权限模型与上述前置条件不同，实施时只调整部署适配层，不改变构建产物和发布目录模型。

## 8. API 与安全边界

当前前端以相对路径请求 `/api/v1/admin/**`。由于本次不部署后端：

- 首页和前端路由必须可以访问
- 登录与业务请求不可用属于预期
- Nginx 对 `/api/` 返回 503，不把 API 请求回退为 HTML
- 不为临时 IP 访问降低前端现有认证、Cookie 或 CSRF 规则

公网 HTTP 只适合本阶段静态页面验收。正式启用管理员登录前必须绑定域名、配置可信 HTTPS 证书，并将 `/api` 同源反向代理到后端服务。

## 9. 测试与验收

### 9.1 仓库验证

- `pnpm check`
- `pnpm test`
- `pnpm build`
- 断言 `dist/index.html` 和静态资源存在
- 使用 Nginx 配置静态检查或容器化语法检查验证配置语法
- 对部署脚本运行 Shell 语法检查
- 断言 `test → 测试环境`、`main → 生产环境` 是仅有的合法分支映射
- 断言测试参数与生产参数交叉组合时部署脚本立即失败且不修改发布目录

### 9.2 发布验证

- ECS 本机 `http://127.0.0.1/` 返回 200
- 公网 `http://8.163.84.24/` 返回 200 且页面标题正确
- 任意前端路由刷新返回 `index.html`，例如 `/login`
- `/api/` 返回 503，不返回前端 HTML
- 静态资源返回 200
- 云效流水线显示构建、发布和健康检查全部成功

### 9.3 回滚验证

部署脚本至少通过可控失败场景验证：在新版本健康检查失败时，`current` 恢复到上一版本，旧页面仍可访问，流水线以非零状态结束。

- 测试 Flow 能从 GitHub 代码源构建并发布到测试 ECS 主机组
